# ÇAHSPAR Index: first development milestone

This branch replaces the placeholder with a Quarto-native explorer at the existing `cahspar-index.html` URL. It retains the association’s six dimensions, institutional colours, navigation, British English source language and translation system. It adds no framework, external script, account, tracking or runtime dependency.

## Research and product direction

The association’s original brief concerns monitoring Türkiye over time; international coverage is not yet specified. The country comparison is a proposed interface direction inspired by the Legatum rankings page, not a decision about the final study population. No Legatum scores, assets or proprietary data have been copied.

Reference pages reviewed:
- https://github.com/isikvlknhu/cahspar.org.tr/blob/main/cahspar-index.qmd

## Included

- Six sortable dimensions plus an illustrative overall score.
- Search with accent-insensitive country names and country codes.
- Region and sample-year filters; score/rank views; reset.
- Up to three-country comparison, retained across filters.
- Country profile with dimension bars and an accessible fixed-scale trend chart.
- Filtered-year CSV download, explicitly labelled synthetic.
- Candidate indicator dictionary, proposed methodology stages and planned data sources.
- Keyboard controls, live counts, loading/error/empty states, reduced-motion support and responsive layouts.

## Data contract and prototype calculation

`assets/index/demo-data.json` contains **invented fixtures**, not actual national statistics or research findings. Its ten countries and three sample years exist solely to exercise the interface. The application requires `status: synthetic-demo`; do not relabel official data as a demo to bypass this guard. A production data release needs a separate reviewed ingestion and validation path.

Each country has a stable code, display name, region and records keyed by sample year. Each record has six dimension scores. Values must be numeric in [0, 100] or missing (`null`/omitted). Duplicate codes/years and invalid scores fail loading visibly.

The illustrative overall score is the arithmetic mean of all six available dimension scores, rounded to one decimal. A missing dimension makes the overall score missing. Missing values are displayed as an em dash, sorted last, and never treated as zero. Trend lines break at missing observations. Ranks are competition ranks (1, 1, 3), calculated on the displayed one-decimal overall scores or the individual dimension scores across the full sample for that year. Filters do not recalculate ranks. Rank-view sorting follows score direction; descending scores places rank 1 first.

The CSV exports the currently filtered countries and selected year, with scores regardless of display mode. Every row contains `SYNTHETIC DEMO - NOT OFFICIAL`, and the filename identifies it as a demo. Comparison always displays scores, as labelled.

## Decisions needed before official results

1. Confirm the primary unit: Türkiye time series, international comparison, subnational comparison, or a combination.
2. Approve a substantive indicator set, definitions, denominators, disaggregations and source-series identifiers. The six CSV candidates are an initial discussion aid, not sufficient coverage for a composite index.
3. Audit actual coverage, licensing, revisions and lag by year and geography. Record observation years separately from edition years; do not silently combine latest values from different years.
4. Agree favourable direction, fixed normalisation bounds, baseline, weights, aggregation, coverage thresholds and treatment of missing data. The gender-gap candidate needs a precise definition (signed gap or absolute distance from parity).
5. Assess overlap (for example, excessive working hours may overlap working life and sustainability), sensitivity to weights and normalisation, and ranking uncertainty.
6. Publish a versioned Türkiye pilot with source observations, transformation steps, provenance, code and a reviewed methodology report before any official ranking.

Recommended production observation fields: indicator ID, geography code, observation year, value, unit, population/denominator, source URL and series ID, retrieval date, revision/version, quality flags and methodological breaks. Preserve raw data separately from derived scores.

## Build and review

Run `quarto render cahspar-index.qmd`, then serve `_site/` over HTTP (JSON loading will not work through `file://`). Full-site deployment remains the existing GitHub Pages workflow on `main`; this branch does not change that workflow or deploy to the live domain.

Only source files should be reviewed for this milestone; `_site/` is generated by Quarto and rebuilt by CI. The original project `sources/` mirror is untouched.

Calculation and data-contract tests can be run with `deno test --allow-read tests/index-core.test.mjs` (Deno is also bundled with Quarto). These cover valid zero values, missing observations, equal weights, ties, rounding, invalid data, accent-insensitive search and the shipped dataset.
